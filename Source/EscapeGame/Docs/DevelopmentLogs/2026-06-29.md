### 遇到的问题

1. 测试中直接创建 `UDialogueQuestSubsystem` 失败：

```text
Object None of class /Script/EscapeGame.DialogueQuestSubsystem with ClassWithin of /Script/Engine.GameInstance was created in invalid Outer
```

原因是 `UDialogueQuestSubsystem` 继承自 `UGameInstanceSubsystem`，不能用无 Outer 的 `NewObject<UDialogueQuestSubsystem>()` 创建。

2. `UDialogueWidget` 不存在时，PlayerController 中的 `TSubclassOf<UDialogueWidget>` 和 `TObjectPtr<UDialogueWidget>` 触发 UHT 错误：

```text
Unable to find 'class' with name 'UDialogueWidget'
```

3. `WBP_Dialogue` 中的 `BindWidget` 一度绑定失败。原因是控件名虽然接近，但实际控件类型不是 C++ 声明的 `UTextBlock`。

### 纠错与解释

- `UGameInstanceSubsystem` 测试中应先创建 `UGameInstance`，再以它作为 Outer 创建 Subsystem：

```cpp
UGameInstance* GameInstance = NewObject<UGameInstance>();
UDialogueQuestSubsystem* Subsystem = NewObject<UDialogueQuestSubsystem>(GameInstance);
```

- 自动化测试不是替代完整游戏流程，而是把逻辑层小切片先固定住，避免等 NPC、UI、蓝图资产都接完后才发现底层状态更新错误。
- `BindWidget` 的条件是：

```text
C++ 属性名 == WBP 控件名
C++ 属性类型 == WBP 控件类型
```

例如 `TObjectPtr<UTextBlock> SpeakerContextTextBlock` 必须绑定到名为 `SpeakerContextTextBlock` 的 TextBlock，不能绑定到 EditableText 或 EditableTextBox。

### 学到的东西

- `ActiveSession` 负责当前这一次会话的即时状态，`DialogueRuntimeMap` 负责长期对话进度记录。
- 自动化测试可以直接构造 `UDialogueDefinition`、节点、选项和运行时状态，验证 `SelectOption` 的状态变化。
- 对于 UE 子系统，测试对象创建也要遵守 UE 生命周期和 Outer 规则。
- UMG 的可视化层级正确不等于 C++ 绑定正确；绑定还要求类型完全匹配。

## 17:45 - Dialogue GetAvailableOptions 最小条件筛选

### 本阶段目标

在 `SelectOption` 最小闭环通过后，继续推进 `GetAvailableOptions` 的最小条件筛选，让当前节点选项不再无条件全部显示。

### 学习目标

- 理解 `GetAvailableOptions` 负责筛选当前节点可显示选项，不能修改运行时状态。
- 理解 `EvaluateCondition` 只判断单条条件，多个条件由 `GetAvailableOptions` 组合。
- 用 Automation Test 先验证“条件不满足时隐藏”，避免测试只覆盖旧实现也能通过的正向路径。
- 理解 `FDialogueCondition` 是数据化的 if 语句，`bInvert` 是数据层表达逻辑取反的方式。

### 已完成内容

- `GetAvailableOptions` 从“原样返回当前节点选项”推进为“逐个选项检查 Conditions”。
- `EvaluateCondition` 最小支持：
  - `EDialogueConditionType::GlobalFlagIs`
  - `EDialogueConditionType::DialogueNodeSeen`
- 不支持的条件类型默认返回 `false` 并输出 Warning，避免条件未实现时错误放行选项。
- `EvaluateCondition` 统一支持 `bInvert`。

### 修改文件

- `Dialogue/DialogueQuestSubsystem.cpp`
- `Tests/DialogueQuestSubsystemTest.cpp`

### 执行命令 / 验证方式

在 Unreal Editor 中编译 C++。

在 Automation Test 中运行：

```text
EscapeGame.Dialogue.GetAvailableOptions.GlobalFlagConditionShowsMatchingOption
EscapeGame.Dialogue.GetAvailableOptions.GlobalFlagConditionHidesNonMatchingOption
EscapeGame.Dialogue.GetAvailableOptions.DialogueNodeSeenConditionHidesUnseenOption
EscapeGame.Dialogue.GetAvailableOptions.DialogueNodeSeenConditionShowsSeenOption
```

### 验证结果

```text
EscapeGame.Dialogue.GetAvailableOptions.GlobalFlagConditionShowsMatchingOption -> PASS
EscapeGame.Dialogue.GetAvailableOptions.GlobalFlagConditionHidesNonMatchingOption -> PASS
EscapeGame.Dialogue.GetAvailableOptions.DialogueNodeSeenConditionHidesUnseenOption -> PASS
EscapeGame.Dialogue.GetAvailableOptions.DialogueNodeSeenConditionShowsSeenOption -> PASS
```

当前 `GetAvailableOptions` 最小条件筛选已验证：

- `GlobalFlagIs` 条件匹配时返回选项。
- `GlobalFlagIs` 条件不匹配时隐藏选项。
- `DialogueNodeSeen` 要求的节点未看过时隐藏选项。
- `DialogueNodeSeen` 要求的节点已看过时返回选项。

### 遇到的问题

1. 第一版 `GlobalFlagConditionShowsMatchingOption` 测试只能验证“条件满足时显示”，旧的“原样返回选项”实现也能通过，因此不是有效 RED 测试。
2. `GetAvailableOptions` 初次实现时曾把循环写成遍历刚创建的 `AvailableOptions`，导致循环永远不执行。正确来源应是 `CurrentNode.Options`。
3. 修改源码后如果没有重新编译，Automation Test 仍会运行旧二进制，日志中会继续出现旧的“尚未落地条件筛选”提示。

### 纠错与解释

- 条件筛选的第一个 RED 测试应覆盖“条件不满足时隐藏”，这样旧实现必然失败。
- `GetAvailableOptions` 的职责是：

```text
读取当前节点
遍历 CurrentNode.Options
对每个 Option 的 Conditions 逐条调用 EvaluateCondition
全部通过才加入 AvailableOptions
返回 AvailableOptions
```

- `EvaluateCondition` 的职责是：

```text
只判断一条 FDialogueCondition
不修改 ActiveSession、DialogueRuntimeMap、GlobalFlagMap 或任务状态
```

### 学到的东西

- 自动化测试必须能先失败，才能证明它测到了当前缺口。
- `GlobalFlagIs` 读取 `GlobalFlagMap[FlagID].bValue`。
- `DialogueNodeSeen` 读取 `DialogueRuntimeMap[ActiveSession.DialogueID].SeenNodeIDs`。
- `ExpectedBoolValue` 可表达期望状态，`bInvert` 可在最终结果层统一取反。
