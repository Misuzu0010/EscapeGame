### 遇到的问题

1. `WBP_Dialogue` 中的选项不需要手动拖入多个 Option Widget。  
   动态选项应由 `UDialogueWidget::RefreshFromDialogue()` 根据 `GetAvailableOptions()` 创建。

2. `WBP_DialogueOption` 的层级和命名需要和 C++ 匹配。  
   最小要求是：
   - `OptionButton`
   - `OptionTextBlock`

3. `ADialogueNPC` 早期只有对话组件，没有默认人物模型组件。  
   这会导致蓝图继承后缺少统一的可替换 Mesh 槽位。

4. 表现层扩展容易过早膨胀。  
   例如转身、表情、镜头、语音、手势都可能需要，但当前不应直接塞进 `ADialogueNPC`。

### 纠错与解释

- `ADialogueNPC` 只应负责可交互入口、对话参与者组件和基础可视模型，不应该承担任务、奖励、对话规则或 UI 绘制职责。
- 转身面向玩家后续应优先复用 `UDialogueParticipantComponent::bFaceInstigator`，不要在 `ADialogueNPC` 上重复造字段。
- 表情、说话动作、语音等更适合后续作为节点级表现数据或表现层 Effect，而不是当前直接写进 NPC Actor。
- 当前最小原型阶段应先验证真实 Dialogue DataAsset，而不是提前实现完整 Quest / Reward / SaveGame。

### 学到的东西

- Dialogue 系统当前已经从纯运行时逻辑测试推进到“可接真实 WBP 和 DataAsset”的阶段。
- UI 层应该消费 Subsystem 的当前状态，不应该自己保存对话规则。
- 子选项 Widget 适合做成可复用的按钮单元，由父 Dialogue Widget 动态创建。
- 任务系统接入前，必须先确认对话本体闭环在地图中真实可用。

### 当前代码层面的缺口

- `StartQuest` effect 尚未实现。
- `QuestStateIs` condition 尚未实现。
- `AddObjectiveProgress` effect 尚未实现。
- `GiveItem` / `GrantReward` 尚未接入背包或奖励队列。
- `OnEnterEffects` 字段存在，但进入节点时尚未执行。
- `FDialogueNode::Conditions` 字段存在，但节点跳转时尚未检查。
- UI 目前显示的是 `SpeakerID.ToString()`，尚未映射到 `DialogueParticipantComponent.DisplayName`。
- `FInterruptPolicy` 只是数据，尚未真正响应走远、开菜单、死亡、进战斗等中断事件。
- `UEscapeDialogueSaveGame` 只是容器，尚未实现 RuntimeMap 与 SaveRecord 的映射。

### 遇到的问题

1. `DialogueWidgetClass` 未配置时，StartConversation 已经成功，但 UI 无法创建：

```text
对话 UI 打开失败：请在 PlayerController 蓝图里设置 DialogueWidgetClass。
```

这会导致系统进入“对话已打开但 UI 不可见”的状态，后续再次按交互键会触发：

```text
StartConversation 失败：当前已有对话正在进行。
```

2. `DialogueWidgetClass` 下拉一开始看不到 `WBP_Dialogue`。  
   原因是 Widget Blueprint 需要确认父类为 `DialogueWidget`，并完成 Compile / Save / 蓝图刷新。

3. 选项数据存在但屏幕不显示。  
   通过日志确认 `CurrentNode.Options=2` 且 `AvailableOptions=2`，随后继续确认 `OptionsBox` 子项数量为 2，最终定位到 `WBP_DialogueOption` 布局问题。

4. `WBP_DialogueOption` 使用 Canvas Panel 作为根布局时，作为 `VerticalBox` 子项容易出现尺寸和位置不符合预期的问题。  
   动态列表项更适合使用：

```text
SizeBox
  Button (OptionButton)
    TextBlock (OptionTextBlock)
```

### 纠错与解释

- 输入层不应该直接调用 `StartConversation`。正确链路是：

```text
E 键 -> InteractAction -> UInteractComponent::OnInteract
-> Sweep 命中实现 UInteractableInterface 的 Actor
-> IInteractableInterface::Execute_Interact
-> ADialogueNPC::Interact_Implementation
-> UDialogueQuestSubsystem::StartConversation
```

- `DialogueWidget` 不应该自己遍历世界寻找 NPC。  
  当前会话的 NPC 来源已经在 `StartConversation(Instigator, Participant)` 里，因此 Subsystem 保存 `ActiveParticipantComponent` 是更清晰的数据流。

- `OptionsBox` 中已经有子项时，问题不在 DataAsset 或 `GetAvailableOptions`，而在子 Widget 的布局、可见性、尺寸、颜色或绑定。

### 学到的东西

- 日志定位应按链路逐段缩小：

```text
输入是否触发
是否扫到 Actor
是否 StartConversation
是否创建 UI
当前节点 Options 数量
筛选后 AvailableOptions 数量
OptionsBox Children 数量
子 Widget 布局是否可见
```

- `VerticalBox` 中的动态子 Widget 应该是自带尺寸的列表项，不应依赖 Canvas Panel 绝对坐标。
- 真机/地图中的 UI 闭环比 Automation Test 更容易暴露 WBP 布局问题。
